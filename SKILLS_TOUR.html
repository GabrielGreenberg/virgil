1. Big picture

Virgil's skill base divides cleanly in two, mirroring the app's own architecture:

              ┌───────────────────────────────────────────┐
              │              VIRGIL (the app)             │
              │                                           │
              │   ┌──────────────┐    ┌──────────────┐    │
              │   │  Library tab │    │  Editor tab  │    │
              │   │  (a folder   │    │  (a paper    │    │
              │   │  of sources) │    │   you write) │    │
              │   └──────┬───────┘    └──────┬───────┘    │
              └──────────┼───────────────────┼────────────┘
                         │                   │
                         ▼                   ▼
              ┌──────────────────┐  ┌──────────────────┐
              │ /library/* (19)  │  │  /editor/* (13)  │
              │                  │  │                  │
              │ catalog & source │  │ in-paper cowork  │
              │ ingestion +      │  │ (footnotes,      │
              │ structural       │  │  citations, bib  │
              │ cleanup of PDFs  │  │  reviews, todos, │
              │ & .docx into     │  │  suggestions,    │
              │ Virgil paper     │  │  style merges)   │
              │ folders          │  │                  │
              └──────────────────┘  └──────────────────┘
                         │                   │
                         └────────┬──────────┘
                                  ▼
                         ┌─────────────────┐
                         │ /editor/        │ ← cross-cuts the two,
                         │  sync-bib-to-   │   safe under flock
                         │  library        │
                         └─────────────────┘
  • Library — your ~/Virgil-Library/ folder. Skills take raw sources (PDFs, .docx, .bib) and turn them into indexed, structurally-clean Virgil paper folders with authenticated bibliography entries.
  • Editor — a single paper you're writing. Skills drain an inbox of AI requests the user files from the UI (footnote here, find me a citation for X, draft a revision of this paragraph).
  • Repo-level — a small set of dev/release skills (cleanup-virgil, cleanup-worktrees, virgil:start).

Both halves share the same architectural pattern: the frontend writes intent files to disk; a Claude session reads them, does work, writes results back, bumps a version stamp, and the frontend polls for the bump and refreshes. More on that ↓

2. The shared cowork pattern

Every Virgil skill is a participant in one of two near-identical loops. Understanding this one diagram is most of what it takes to grok the whole skill base.

   Frontend                              Claude (separate session)
     │                                      │
     │  user clicks "AI: add a footnote" ─► │
     │  writes intent to                    │
     │  ai-requests.json                    │
     │                                      ◄ /editor/review reads
     │                                      │
     │                                      │   ┌─────────────────┐
     │                                      │   │ work happens    │
     │                                      │   │ (read .tex,     │
     │                                      │   │  search bib,    │
     │                                      │   │  Crossref, etc) │
     │                                      │   └─────────────────┘
     │                                      │
     │  notes.json / footnotes.json      ◄ Claude writes back via
     │  ai-requests.json (status=done)      apply_response.py:
     │  notifications.json                    • new card
     │  version.txt (bumped)                  • status flip
     │                                        • notification append
     │                                        • version bump
     │                                      │
     ◄ polls version.txt every 6s,          │
       reloads sidecars on bump             │
The load-bearing constraint: the frontend never invokes Claude directly. It writes intent files; Claude drains them. This decoupling is why you can run /loop /library/index-pending in one terminal and keep clicking around the Library UI in your browser without anything synchronizing.

Concurrency & locks (library only)

Three shared files — master.bib, .virgil/catalog.json, .virgil/notifications/inbox.json — are protected by POSIX fcntl.flock sidecar locks. Skills mutate these only through CLI shims (update_master_bib_entry.py, update_catalog_entry.py, append_inbox_item.py). That's what makes it safe to run /library/deep-index, /library/index-paper, and /library/authenticate-bib in parallel on different citekeys.

Two write conventions for skill output

  • Direct creates (draft-footnote, find-citation, draft-quotation) — insert the result into the paper. User can delete if unwanted.
  • Suggestion cards (everything in the answer-* family + draft-suggestion) — emit an author: "ai" card with status: "pending". User accepts or rejects.

3. Library skills — 19 callable + 2 shared includes

The Library subsystem lives at library/. Skill source is in library/skills/; build mirrors to .claude/commands/library/. Read library/AGENTS.md for the full spec.

⚙ Setup & meta — get the pipeline working / develop the skills themselves
heavy/library/setup — Install the ML extraction toolchain (marker, PyMuPDF, ocrmypdf, tesseract, poppler) and pre-cache marker's ~1 GB of model weights into the library itself.
Why library-local models: shared across index-paper + deep-index re-reads, no global cache pollution.
Idempotent: only installs what's missing. Pass --force to redo.
Args: none. library/skills/setup.md
dev-only/library/iterate-skill — Stress-test a library skill against a corpus of citekeys, read the subagent's critique memo, edit the skill markdown, loop.
For: Virgil maintainers iterating on the skill files themselves.
Args: <skill-name> <citekey1> [citekey2] ... library/skills/iterate-skill.md
📥 Inbox drains — run these in a /loop for steady-state processing
drain/library/index-pending — One-pass drain of every queue file: triage, index, authenticate, deep-index, bib-edit, paper-review.
Pair with: /loop /library/index-pending for steady-state polling.
Args: none. library/skills/index-pending.md
drain/library/ai-requests — Take a pass on user-authored AI requests on library papers (notes attached to queue entries + paper-review requests).
Distinct from index-pending: that drains the indexing queue; this drains review requests the user filed on already-indexed papers. library/skills/ai-requests.md
📑 Per-source ingestion — raw file → Virgil paper folder
light/library/triage-pdf — Triage one newly-dropped file in unsorted/: propose a citekey, move into papers/<citekey>/, queue for indexing (or auth for .bib drops).
Accepts: PDF, DOCX, .tex, .bib.
.bib drops: multi-entry fan-out — each entry becomes a bib-only catalog row.
Args: <filename> (relative to unsorted/). library/skills/triage-pdf.md
heavy/library/triage-pending — Batch-triage every file in unsorted/: propose citekeys for the whole inbox, surface them for review, apply in one transaction.
Args: optional auto to skip the review step. library/skills/triage-pending.md
light/library/index-paper — Extract LaTeX from a PDF/DOCX/.tex source. Produces papers/<citekey>/main.tex (with \pgmark{N} anchors for PDFs), a single-entry references.bib, empty sidecars, and an authenticated catalog row.
Uses marker for PDFs (layout-aware, equation-aware, footnote-zone-aware).
Args: <citekey>. library/skills/index-paper.md
light/library/fuse-alternate — Add printed-page \pgmark{N} anchors from a PDF source to a paper that was originally indexed from a DOCX or TEX (which carry no pagination).
Reads from papers/<citekey>/variants/.
Args: <citekey>. library/skills/fuse-alternate.md
🔖 Bibliography — authenticate entries, apply edits, merge across the library
light/library/authenticate-bib — Verify and look up a single bib entry against Crossref / OpenAlex / Semantic Scholar / arXiv. Updates master.bib + sets bib.state.
Five terminal states: authenticated (DOI verified or ≥2 sources agree), unverified, failed, manuscript, canonical.
Args: <citekey>. library/skills/authenticate-bib.md
light/library/apply-bib-edit — Save a manual bib edit the user made through the library UI's "Edit" button. Reads from the queue, rewrites the master.bib block, re-emits references.bib.
Args: <citekey>. library/skills/apply-bib-edit.md
heavy/library/merge-bibs — Walk every deep-indexed paper's references.bib and fold each entry into master.bib — authenticate, dedupe, or split as needed.
Self-defending: pre-run snapshot to ~/Library/Application Support/Virgil/backups/, refuses to start if another writer is active, forces --batch 1 in cloud-synced libraries unless --allow-parallel-sync.
Skips transient entries (manuscript / forthcoming / in press / draft) — authenticating them is doomed for non-content reasons. library/skills/merge-bibs.md
🔬 Deep-index family — polish an already-indexed paper (single ✓ → ✓✓)

An umbrella skill plus six subskills that handle different polish phases. The subskills are also callable directly when only one phase needs work.

umbrellaheavy/library/deep-index — Polish an already-indexed paper: structure, headings, footnotes, pagination, bibliography. Runs a convergence loop (no cap) until two passes find nothing new.
Orchestrates the six subskills below. Two-phase: deterministic preprocess (deep_preprocess.py) then AI structural pass.
Status produced: deepIndexed (✓✓ idx).
Args: <citekey> [--fresh]. library/skills/deep-index.md
subskill/library/di-preflight — Detect metadata mismatches, strip lending-slip / JSTOR boilerplate, identify multi-article scans, dispatch OCR recovery, route by genre.
Step 0 / 0.5 of deep-index. library/skills/di-preflight.md
subskill/library/di-clean-prose — Fix the title, headings, heading hierarchy, drop caps, and align pagination anchors.
Step 3a / 3b / 3c of deep-index. library/skills/di-clean-prose.md
subskill/library/recover-footnotes — Re-attach orphan footnotes to their callouts, handle endnote-style sources, fix truncated/leaked footnote text. Walks the full Tier 0 → Tier 4 ladder.
Step 3d of deep-index. library/skills/recover-footnotes.md
subskill/library/clean-bibliography — Itemize the References section, emit a clean references.bib, rewrite inline citations to a uniform style.
Step 3e / 3f / 3g of deep-index. library/skills/clean-bibliography.md
subskill/library/di-examples — Convert numbered examples to the expex package; format formal-semantics math in linguistics/philosophy papers.
Step 3h₁ / 3h₂ of deep-index. library/skills/di-examples.md
subskill/library/di-validate — Validate pagination anchors, produce an audit punch-list, classify outstanding work by category.
Step 3i + 9.5 of deep-index. Also callable directly for a status check on an already-deep-indexed paper.
library/skills/di-validate.md
📜 Shared doctrine — transcluded by the deep-index family, not callable as commands
include_doctrine.md — §0.5 Scope doctrine, §Persistence convergence, §9 outstanding-work categories, anti-patterns, self-check. The load-bearing rules every subskill inherits.
Build script filters leading-underscore files out of the command mirror. library/skills/_doctrine.md
include_latex-output.md — The allowed LaTeX command vocabulary for deep-index output — what parseLatex() in Virgil can handle.
library/skills/_latex-output.md

4. Editor skills — 13 skills

The editor-side skill set lives at editor/. Skill source is in editor/skills/. Read editor/AGENTS.md for the full spec.

All editor skills act on a single Virgil paper folder. They consume three intent surfaces:

  1. virgil/ai-requests.json — the unified queue (kinds: footnote, note, quotation, citation, todo, suggestion, style-merge).
  2. Card-level aiRequest: boolean flags on notes, todos, cutter-comments, revision-comments — bridged into the unified queue on toggle.
  3. virgil/bib-review-requests.json — per-bib-key reviews (kept separate because it's per-bib-key, not per-paragraph).
📋 Umbrella — the one skill that handles everything
umbrella/editor/review — Take a pass on a Virgil paper: walk the unified request inbox, dispatch each request to the matching specialist as a subagent.
The skill the user invokes 95% of the time. Calls every other editor skill as a subagent when there's something to do.
Args: <docPath> (optional — falls back to cwd if it has a virgil/ subdir). editor/skills/review.md
✏️ Direct creates — insert into the paper without a suggestion wrapper
/editor/draft-footnote — Write a footnote into footnotes.json and insert the LaTeX command at the anchor paragraph.
Triggered by: aiRequest on a footnote-shaped request, or user explicitly says "Virgil, footnote this claim."
Args: <docPath> <requestId>. editor/skills/draft-footnote.md
/editor/find-citation — Search Crossref / OpenAlex / Semantic Scholar / arXiv for a citation matching the user's description; add to references.bib and create a citation card.
Distinct from /editor/answer-bib-review (which verifies an existing entry).
Args: <docPath> <requestId>. editor/skills/find-citation.md
/editor/draft-quotation — Pull a quotation (or several) from a source into a paragraph. Assembles a QuotationGroup anchored to the paragraph.
Args: <docPath> <requestId>. editor/skills/draft-quotation.md
💬 Responders — emit suggestion cards instead of editing in place
/editor/answer-note-request — Answer a note the user left in Virgil's Notes panel asking for AI help. Drafts a sibling note anchored to the same paragraph (or a suggestion card if the user wanted a doc edit).
editor/skills/answer-note-request.md
/editor/answer-todo-request — Take care of a todo the user marked for AI in the Todos panel. Decides whether it asks for a doc edit, a footnote/citation, or analysis, and delegates accordingly.
editor/skills/answer-todo-request.md
/editor/answer-cutter-comment — Respond to a comment the user flagged on a cut/excerpt in the Cutter panel. Drafts a suggestion card responding to the comment.
editor/skills/answer-cutter-comment.md
/editor/answer-revision-comment — Respond to a comment in the Revisions panel. Drafts a sibling revision-comment (or a revision-suggestion if the user asked for an actual edit).
editor/skills/answer-revision-comment.md
/editor/draft-suggestion — Propose a revision to a paragraph. Creates a revision-suggestion card with author: "ai" for the user to accept or reject.
Important: does NOT edit the document directly — it always goes through a suggestion card.
editor/skills/draft-suggestion.md
📚 Bibliography — per-entry verification and whole-paper library sync
/editor/answer-bib-review — Fill in or verify a single bib entry that's been flagged for review. Three modes: type=fields (verify/fill), type=notes (draft annotation), --library-sync (swap in a library entry).
Args: <docPath> <bibKey> [--library-sync <libraryCitekey> --library <path>]. editor/skills/answer-bib-review.md
cross-cut/editor/sync-bib-to-library — Tidy a paper's whole bibliography against the user's Virgil Library: swap matched entries to the library's authoritative version, rename citekeys throughout the doc, add missing entries to the library.
The only editor skill that writes to the library. Single-session cross-cutting via the library's flock-protected Python shims — safe to interleave with a parallel /loop /library/index-pending.
Args: <docPath> [--dry-run] [--library <path>]. editor/skills/sync-bib-to-library.md
🎨 Style — preamble merges
/editor/style-merge — Apply the user's preamble customizations to a document's current style. Intelligently merges user's local LaTeX preamble tweaks onto the target style and rewrites the .tex.
Doesn't trigger for general formatting changes ("make headers bigger") — those need a manual preamble edit by the user first.
Args: <docPath>. editor/skills/style-merge.md
🛠 Meta — dev-only
dev-only/editor/iterate-virgil-editor — Stress-test & refine the editor skill set in a sandboxed sample paper. Synthesizes representative AI requests, sandboxes samples/annotation-history, runs the target skill via subagents, reads critique memos, edits skill markdown, loops.
Args: [<skill-name>] [<max-attempts>]. editor/skills/iterate-virgil-editor.md

5. Repo-level skills

These don't live under editor/ or library/ — they're top-level workflows tied to maintaining or releasing Virgil itself, or to running it.

release/cleanup-virgil — Full Virgil release cleanup: merge worktrees, bump version, push and deploy both the app and the library bundle.
End-to-end release workflow.
/cleanup-worktrees — Clean up all git worktrees and merge them back into main.
Subset of /cleanup-virgil — just the worktree merge step.
/virgil:start — Front-door for Virgil — orients the user, resolves their paper and library context, dispatches to the right specialist (editor or library skill).
The skill that fires when someone says "hey Virgil" or "Virgil, <anything>" without naming a specific skill. Also handles first-time onboarding.
Lives in the user's global Claude config, not in the repo.

6. How the skills are built & shipped

Skills are markdown files in library/skills/*.md and editor/skills/*.md. Two destinations:

  1. Repo-local: npm run build:library-bundle and npm run build:editor-bundle mirror skills to .claude/commands/library/ and .claude/commands/editor/ respectively. Both auto-run via predev / prebuild hooks. Files starting with _ are excluded — they're transclusion includes.
  2. End-user folder sync: the library build also emits to public/skill-bundle/. When a user opens a Virgil paper or library folder, a per-folder sync gated by a version stamp copies the latest skills into .claude/commands/ and .virgil/scripts/ inside their folder. Updates appear as a "click to refresh" toast (not skipWaiting).

The editor-side end-user folder sync isn't built yet — see "Future work" in editor/AGENTS.md.

How to amend this doc: it's plain HTML/CSS in SKILLS_TOUR.html. Edit any section, no build step. To regenerate the descriptions, source-of-truth is the YAML-frontmatter description: field in each skill markdown file.
