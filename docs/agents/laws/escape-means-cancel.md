# Escape means cancel

> **Escape ABANDONS. It is never the key that saves, and it is never a synonym for whatever a click elsewhere would have done.** Wherever a surface or a field can END in more than one way, the endings are separate CHANNELS with separate names — a COMMIT (a button, Return), a DISMISS (click-away, blur), and a CANCEL (Escape, and any control whose own label names Escape). Two of those may coincide; they may never be *forced* to coincide by sharing one prop.

The defect this law names is not a wrong decision — it is an **undecided** one. Escape is folded into a close channel that already existed, nobody states what it should mean, and the affordance the user reaches for to back out becomes the fastest way to commit. Both halves below shipped green under every test the repo had, because each site's tests spelled the ending the same way the site did.

## The field half (task 555)

Five fields were filed as presenting Escape as a cancel while actually committing; checking the list against the memo-era commit found the real population was **one** — `CitationCard`'s Code box, which holds a draft *and* debounces a write behind it. It ended Escape through the same handler as Enter (`e.key === "Enter" || e.key === "Escape"`), and that aliasing is precisely what had removed it from task 529's census: a handler naming both keys was classified as a field whose `onChange` commits every keystroke, for which the alias is harmless. **An alias is what takes a site OUT of the population**, so the one field where the alias was a lie was the one field the guard could not see.

The remedy is 529's door, not a third spelling: Escape drops the pending debounced write, restores the command the session *opened* with (an earlier debounce may already have landed), and ends the session exactly once. The census that replaced the hand list DISCOVERS the aliasing population and pins it as an exact set with each member's reason. CI: `citation-code-escape-cancel.test.tsx`, `field-edit-session.test.tsx`.

Two corollaries the same sweep fixed, both in [a-nodeview-owns-its-timers-lifetime.md](a-nodeview-owns-its-timers-lifetime.md): a cancel must undo what **the session** did and never what someone else did (the baseline moves with a foreign write), and a session that ends by UNMOUNT ends zero times unless the component's lifetime scope ends it, because React dispatches no `blur`.

## The surface half (task 687)

A floating surface ends through three exits — DISMISS (click-outside), CANCEL (Escape, the header ×), COMMIT (a button, Return). [`useMenuDismiss`](../../../src/components/menu/useMenuDismiss.ts) routed the first two through one `onClose` prop, which is harmless for ~20 menus that stage nothing: with no draft in hand, dismissing and cancelling are the same act.

Then a **deferred-commit** surface arrived. `CitationCreatePopover` stages citekeys and materializes the `\cite` only on commit — and committing on click-away is a deliberate, good design there (the user built a citation and went elsewhere; they get it). So it bound the commit chokepoint to the one close channel it was given, `onClose={commitAndClose}`, and **Escape inserted the citation the user pressed it to abandon**, with no way out short of removing every staged chip by hand. Nothing decided that; a prop was reused.

The fix is a channel split at the primitive, not at the popover: `useMenuDismiss` and `MenuProvider` take an `onCancel` that Escape ends through, **defaulting to `onClose`** so every existing menu is byte-identical, and `BibEntryPickerMenu` → `CitekeyPicker` forward it. A picker's header × goes through the cancel door too — its label reads "Close (Esc)", so it must do what Escape does (the 386/389 "a key must do what its affordance says" family). What a cancel deliberately does **not** undo: staging a library-only key calls `onAddBibEntry` at *pick* time, so an abandoned pick can leave a row in `references.bib`. An uncited BibTeX entry is inert; removing one on an abandon path is a bib mutation that could delete a key cited elsewhere.

**The census discovers its population by the QUESTION, not by a mechanism** (task 404's rule): *which JSX element hands its close channel a function that COMMITS?* Any such element must also hand over a distinct `onCancel`. Not "every element with an `onClose`" — that is the whole menu system, and an allowlist of surfaces that stage nothing is a filing cabinet, not a guard. Stated residual: a commit bound through an identifier named for its subject rather than its verb (`onClose={finish}`), or wrapped inline, is invisible to the text scan and is answered by the MECHANISM legs instead.

CI: [escape-means-cancel-census.test.ts](../../../src/components/menu/__tests__/escape-means-cancel-census.test.ts) (the population leg + the two mechanism legs), `useMenuDismiss.test.tsx` (Escape → cancel, click-outside → dismiss, fallback, the two-stage interceptor still outranking both), `bib-entry-picker-combobox.test.tsx`, and [citation-create-popover-escape-cancel.test.tsx](../../../src/panels/Citations/__tests__/citation-create-popover-escape-cancel.test.tsx) — which drives the REAL chain with a REAL window Escape, because `useMenuDismiss` owns a capture-phase window listener and stops the event before the picker's own keydown handler ever sees it: a mocked picker cannot witness this claim.

## The dialog half (task 876)

A modal question whose two real answers BOTH commit cannot be a boolean: `useConfirmDialog().confirm` resolves Escape/click-away as `false`, so if `false` already means one of the answers, Escape silently picks it. The label-rename "Update references?" was exactly this — `false` meant "Leave references", so Escape renamed the label and orphaned every `\ref`. Such a question goes through the three-way `choose()` door (`confirm` / `secondary` / `cancel`), and the consumer treats `cancel` as ABORT — [`renameLabelWithRefs`](../../../src/lib/tiptap/label-rename.ts) returns `"cancelled"` and writes nothing. Its copy (`labelRenameConfirmCopy`) puts "Leave references" in `secondaryLabel`, never `cancelLabel`. The same door re-validates after the await (`"stale"` if the declaration's label moved, `"conflict"` if another declaration claimed the candidate) — the async-gap law's half of the same defect. CI: `label-rename-refs.test.tsx` (cancel → byte-identical, stale, conflict-under-modal, the producer uses `choose`).

## The hook half (task 1094)

A field's Escape can live somewhere the field's own JSX does not show. The todo card's notes box took its keydown from [`useTabIndent`](../../../src/hooks/useTabIndent.ts), whose Escape BLURRED — beside an `onBlur` commit, so Escape wrote the draft to `todos.json`; its title (`CardTitleInput`) had no Escape at all, so the next click-away wrote it. Both were invisible to the field census, which read only `onKeyDown={…}` attribute text, and a NAMED handler is one identifier long. Fixes: `useTabIndent` takes the field's `cancel` (`(el) => session.cancel(el, () => draft.revert())`) and blurs bare only when none is given — the escape hatch for fields whose blur commits nothing; `CardTitleInput` takes the `useFieldEditSession` door exactly as `CardBodyTitle` does. The census now RESOLVES a named handler to its in-file declaration, and a `useTabIndent(` declaration into the hook's own source plus the `cancel:` it is handed — so an omitted cancel on a blur-commit field reads like a bare `.blur()` and fails. Its door regexes are case-insensitive (`notesSession.cancel(` / `codeSession.cancel(` are the door; the case-sensitive form had misfiled CitationCard's doored Code box as an unmount-family member). CI: [field-edit-session.test.tsx](../../../src/lib/__tests__/field-edit-session.test.tsx) (named-handler resolution, hook canary, hook MECHANISM leg), [todo-escape-cancel.test.tsx](../../../src/panels/Todo/__tests__/todo-escape-cancel.test.tsx).

## The gesture half (task 1167)

A held pointer gesture is the innermost transient thing on screen, so Escape mid-drag ABANDONS it: the one end path's non-committing branch, entered from a window-CAPTURE keydown that `claimGestureKey`s the press (the engine's third invariant, `src/lib/pane-resize/pointer-invariants.ts`). The Outline focus-band edge drag took the engine's two pointer invariants and not this one, so Escape did nothing and the next mouseup committed the boundary; it now ends through `endDrag("cancel")` (restore, no `onSnapBoundary`). The two key-claim legs in `pane-drag-guardrail.test.ts` could not see it — they ask about key handlers that exist — so the **Escape-answer census** asks of EVERY held gesture (both pointer censuses' population): answer Escape through a claimed gesture-scoped handler, or sit in `PERMITTED_ESCAPELESS_GESTURES` under one verdict tag — `[hands-off: …]` (the drop-mode session owns the Escape), `[no-durable-commit: …]`, `[mode-owned: …]`, or `[owed: …]`. The two `[owed]` entries (FloatingPanel move/resize, the strip-icon reorder in `editor-layout/drag-drop.tsx`) are known gaps, stated so they can be routed. CI: `pane-drag-guardrail.test.ts` ("Escape-answer census"), `focus-band-edge-drag.test.tsx` ("Escape cancels").

## The chrome-input half (task 1441)

An editor-chrome input (the paragraph-title strip, the heading label input, the example label pod) is likewise the innermost transient thing on screen, so it CLAIMS the keys it answers — and only those. Task 552 claimed them on the title strip by hand; the expex and heading twins hand-rolled their own keydown with a bare `preventDefault()`, so Escape cancelled the label AND reached `useMarginEdit`'s window cancel (unsaved margin guides lost), a scrimless window's Escape and `NodeEditPopover`. All three now answer through ONE door, [`answerFieldKeys`](../../../src/lib/tiptap/field-keys.ts) (`isCommitEnter` / `isCancelEscape` + `claimGestureKey`); the slash popup's Escape claims too. CI: `chrome-input-key-claim-census.test.ts` (every Escape answered under `src/lib/tiptap/**` or `editor-extensions.ts` claims within its handler arm, or is the door), `label-rename-refs.test.tsx` ("task 1441" window-listener spies).

**The deliberate-press half (task 1448).** Escape CANCELS only when the user pressed it: an Escape typed mid-IME-composition cancels the COMPOSITION, and a held key's auto-repeats are not further presses. Task 1188 taught the menu doors; the dialog doors (`SystemDialog`'s bubble listener, `useNonModalDialogKeys`) still closed a dialog — and its draft — on a composing Escape, and a held Escape over a stacked pair (StyleEditorModal over ManageStylesModal, Fonts over Preferences) closed BOTH, because the stack popped between repeats. Now every Escape gate in both silos spells it `isCancelEscape(e)` ([key-intent.ts](../../../src/lib/key-intent.ts)), and every door that closes a surface answers the first press only and swallows its repeats until keyup (`if (e.repeat) return; swallowRepeatsUntilKeyup(e);`: the two dialog doors, `useMenuDismiss`, `NodeEditPopover`, `useMarginEdit`). CI: `escape-key-census.test.ts` (no bare Escape comparison outside key-intent; every Escape door asks `e.repeat` or sits in `REPEAT_LEDGER` with its reason — inline-field cancel, pointer-gesture cancel, claimed popup), `dialog-escape-intent.test.tsx` (IME and held-repeat legs on both dialog shells).
