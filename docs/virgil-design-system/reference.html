Virgil — Design System Visual LaTeX editor for academic writing · v1 reference Apr 24, 2026 · 11 sections

One system, every panel obeys.

This document is the canonical visual + interaction system for Virgil. It tightens the existing tokens in globals.css and the conventions in STYLE_GUIDE.md, removes overlaps, and gives every component a single specified resting / hover / selected / disabled state. Use it as the reference; ship the redrawn rules in section 11 back to the repo.

What changed, at a glance

Five tightenings drive the rest of this document.

1. Selection has one visual

Today: three selection rings live in code (amber-300, footnote-red, emerald, stone, cut-red).
Now: selected = themed border + themed header at full opacity + white body. No shadow change. amber-300 retired as a generic.

2. Hover has one rule

Light surfaces darken on hover (cards, panels, modals).
Dark chrome lightens on hover (top bar, header bg).
Borders step from edge-subtle → edge-hover.

3. Icons live on a 4 px grid

Three sizes: 14 inline, 16 panel, 20 toolbar. One stroke weight (1.75 px) for outline icons. Hit area always ≥ 22×22.

4. Card themes = 5 tokens

Each theme: badge-bg, badge-fg, badge-border, header-tint, selected-border. Header tint = badge-bg; selected-border doubles as separator-on-select.

5. Buttons are 5, not 9

primary · secondary · warm · danger · ghost. Three sizes (sm / md / lg). Icon-only is its own variant: iconbtn.

6. Hit targets ≥ 22 px

Header icons today range 16–28 px. Locking icon-button hit area to 22×22 (or 28×28 in toolbars) eliminates the mismatched click affordances on every panel header.

Icon sizes

Three sizes only. Choose by location, not by feel.

14 px · inline

Inside text rows: chevron, target arrow, badge cross. Hit area still ≥ 22 px.

16 px · panel

Panel header icons (popout, close, color picker, menu). Hit area 22 × 22.

20 px · toolbar

Top bar, MenuBar, primary toolbars. Hit area 28 × 28.

Stroke & alignment rules

  • Stroke weight: 1.75 for outline icons. 2 only for the X-close glyph (it's a flat shape, not an outline). Never 1.5 or 2.5 mixed in.
  • Stroke caps: round for both line caps and joins. No square caps anywhere.
  • Color: currentColor always; never hard-coded inside the SVG.
  • ViewBox: 0 0 24 24 for outlined icons (Lucide-compatible).
  • AI sun-star: 8-ray, rotated 15°. Never a 5-point star. (See §11.)

What selection does not do

  • Does not change shadow, scale, or padding.
  • Does not color the body — body text is #44403c on white, always.
  • Does not use a generic amber ring. Each theme has its own selected-border. Amber is reserved for drop-targets and label-ref active state.

Deselection

  • Click empty list space → deselect (panels add onClick={() => onSelect(null)} to list container).
  • Esc on a focused card → deselect.
  • Selecting another card replaces selection. No multi-select on cards.

Virgil — Style Guide (v2)

App-wide UI conventions. The system in this guide is the only one we ship. New components must compose from existing primitives; new tokens must replace several hex values, not add to a long list.

1 · Tokens — semantic only

Every panel, card, and button reads from the variables in globals.css. Six rules govern token use:

  1. Use the semantic name (--ink-body) — never the raw hex.
  2. If you find yourself reaching for a Tailwind stone-, red-, or amber- utility, stop. Either there is a token, or you need to add one.
  3. Locked aliases never drift apart. The list (--pod-editor, --h1-color, --h2h3-color, --scrollbar-hover, --theme-color, --main-tab-bg) is closed; do not add to it without strong justification.
  4. New scale tokens go in groups of 5 (50/100/200/300/500). One scale per category color.
  5. The cool tones (sky for AI, blue for archive, blue-grey for LaTeX comments) live exclusively in the components that own them. Never in chrome.
  6. Amber is reserved. Drop targets and label-ref active state only.

2 · Hover

One rule, two directions:

  • Light surfaces darken: resting bg → surface-muted or surface-muted-strong; resting border → edge-hover.
  • Dark chrome lightens: top bar, panel header — bg → rgba(255,255,255,.30–.45), color → --accent.
Forbidden: hover:bg-stone-100 on a chrome (dark) surface; hover:bg-blue-50 anywhere; any cool-toned hover in warm UI.

3 · Selection

One canonical visual:

  • Themed border (theme.borderSelected).
  • Themed header strip at full opacity (theme.headerSelected).
  • White body (--surface).
  • Body text always --ink-body. Never inverted, never tinted.

Click empty list space to deselect. Esc deselects on focus. There is no multi-select for cards.

4 · Focus

Inputs only. Buttons rely on hover; cards rely on selection.

  • Border --edge-subtle → --edge-hover (hover) → --accent (focus).
  • Focus ring: 0 0 0 3px rgba(124,94,60,.15).

5 · Icons

Three sizes, one stroke:

  • 14 px inline · 16 px panel · 20 px toolbar.
  • Stroke 1.75 for outline icons; 2 only for the X close glyph.
  • Round caps and joins; currentColor always; viewBox 0 0 24 24.
  • Hit area always ≥ 22 × 22 (panel) or 28 × 28 (toolbar). Pad the button, not the glyph.
  • The AI sun-star is 8-ray, rotated 15°. Never a 5-point star.

6 · Spacing

4-px grid throughout. Aliases: 2 (hairline), 4 (xs), 8 (sm), 12 (md), 16 (lg), 20 (xl), 24 (2xl), 32 (3xl). Header height locked to --header-h; never override per-panel.

7 · Cards

One wrapper (PanelCard) and one editable variant (EditableCard). Theme is a 5-token record:

  • badge.bg, badge.fg, badge.border
  • header.selected (resting = mix(selected, white, .5))
  • border.selected (also separator-when-selected)

Anchored cards use BadgeLabel; orphans use BadgeOrphaned. Trash is opt-in (onTrashClick) and lives in the absolute overlay; it is never inside the header flex row.

8 · Buttons

Five variants, three sizes:

  • btn-primary · accent fill · one per dialog/screen
  • btn-secondary · neutral · adjacent actions
  • btn-warm · accent-light · prominent non-primary (Restore)
  • btn-danger · transparent → danger-soft on hover
  • btn-ghost · transparent · Cancel, Skip

btn-resolve (emerald) is reserved for the Resolve / Accept actions in review flows; do not use it as a generic positive button.

9 · Inputs

One .input class. Border ladder (subtle → hover → strong → focus). 3-px focus ring at rgba(124,94,60,.15). Search inputs prepend a 14-px icon at 8 px from the left edge.

10 · Modals

All dialogs flow through SystemDialog with five sizes (sm 340, md 380, lg 520, xl 720, full 96vw/1100) and four button variants (primary, danger, secondary, accent). Anchored dialogs accept an anchorRef and position below the trigger. Never call window.alert/confirm/prompt.

11 · Drag & drop

Each draggable category has a fixed ghost: footnote (red), note (emerald), citation (amber), archive (stone), AI (sky), text-only (neutral). Drop targets use the ring/inset-shadow vocabulary in §08.

12 · Editor inlines

Click-to-edit elements (footnote, citation, math, latex-comment) all carry data-click-edit="true". CSS applies a 1-px hover ring in their theme color and cursor: pointer globally. The inline open behavior (popup vs inline expand) is per-element but the affordance is uniform.

13 · Marginalia

22-px markers, 4-px radius, 1.5-px theme border. Two columns per gutter side, 2-px gap. Color identity matches the source panel. Always draggable; keyboard-deletable when focused.

14 · Top bar

Top bar uses the dark-chrome hover rule (lighten). Default icon color is --ink-subtle. Active tabs sit on --main-tab-bg ≡ --background. The AI button is the only top-bar element that uses sky tones (hover:bg-sky-50/50, hover:text-sky-600).

15 · System dialogs & tooltips

Tooltip: 500 ms open, 0 ms close. Style: --ink-strong bg, white text, 11 px Inter, 4 px radius, 6 px gap. Keyboard shortcut indicators always <kbd>.

When in doubt, follow the existing pattern. When the existing pattern doesn't fit, propose a token first; one new token is preferable to one new hex value in code.
